Using the app

Your first workspace

A useful workspace starts with one correctly registered site, a verified tracker, and a small set of events tied to real product questions.

Complete the protected setup

The installer creates the first administrator, organization, and site in one transaction. Use the exact site origin, including https:// and any production subdomain. Requests from other origins are rejected.

After setup, sign in and open the site from Sites. The Overview page shows whether the tracker has sent its first pageview.

Install the tracker

Open Site settings and find Installation snippet. Copy the generated script into the tracked website's HTML, normally just before the closing </head> tag or through its tag/template system.

Open the tracked website in a normal browser tab, navigate between pages, then return to Privacy Analytics. The status changes from Waiting for first pageview to Tracker connected after queued processing completes.

i

The snippet already contains the public site identity and collection endpoint. Do not copy a snippet from one site into another registered origin.

Choose automatic events

Open Tracking & events to control automatic interaction collection. Enable only signals your team will use. Clear event names make reports, conversions, funnels, alerts, and dashboards easier to understand later.

Add events from application code

For interactions your product already knows about, call the tracker directly. Use stable, action-oriented names and non-personal properties:

window.privacyAnalytics?.track('trial_started', {
    plan: 'team',
    source: 'pricing_page',
});

The Tracking and events guide covers allowed values, automatic events, single-page navigation, privacy filtering, rule publishing, and verification.

Use the Visual Event Designer

The Visual Designer opens the registered website with an authenticated, short-lived design session. It can create a general interaction rule or an optional object mapping for any item type you define.

  1. Open Tracking & events.

    Select Open Visual Designer. The target must match the registered site origin.

  2. Choose an element.

    Prefer a stable ID or data attribute over layout-dependent selectors.

  3. Choose the measurement.

    Name a general event by intent, or choose Reusable object to measure individual items across pages and lists.

  4. Test and save.

    General rules are saved as drafts for review. Object mappings can be published from the designer. The tracker fetches configuration remotely.

Add Object Analytics only when useful

Standard page, event, goal, and funnel reports are sufficient for many sites. Use Object analytics when you need performance histories for individual products, content, courses, listings, profiles, campaigns, or another type from your own domain.

Object types are free-form. The templates describe URL and page structures rather than requiring company, job, event, or ecommerce models. See the Object Analytics guide for wildcards, repeating cards, nested relationships, regular expressions, automatic discovery, and portal access.

Define conversions and funnels

Open Goals & funnels. A conversion gives a business name to an important event. A funnel defines an ordered sequence of page and event steps, such as pricing page → signup started → account created.

Keep funnels focused on one decision. Long funnels become difficult to interpret when visitors can legitimately take several paths.

Create page groups

Page groups combine URL patterns into useful content or product areas. They help answer questions such as “How does documentation perform?” or “Which product area gets the most engagement?” without editing every report.

Classify internal traffic

In Site settings, add office or VPN network addresses under Internal traffic. Matching activity remains classified for inspection but is excluded from standard reports by default.

Organizations and access

Organizations provide the tenant boundary for sites and members. Owners and administrators can change site configuration; members can view the sites granted through their organization. System administration remains separate from organization membership.

First-week checklist

  1. Confirm normal traffic.

    Compare pageview volume with a known operational signal and investigate unexpected gaps.

  2. Exclude your team.

    Add office and VPN ranges, then confirm internal traffic appears in traffic-quality reporting.

  3. Name outcomes.

    Create a few conversions for events that represent real product or business success.

  4. Add context.

    Annotate launches, campaigns, incidents, and measurement changes.

  5. Check operations.

    Review Data quality and System health before sharing conclusions from the first reports.
