Before you start

The object-data overview needs no setup. Complete these once for hands-on tracking tutorials; reporting tutorials can use a site that already has data.

  1. 1
    Add your website

    Open Sites, select Add site, and enter the exact public URL including https://.

  2. 2
    Install the base tracker

    Copy the single script shown on the site page into your website. Most tutorials need no further website deployment; use a stable existing selector for interaction rules.

  3. 3
    Confirm the connection

    Visit your website once, return to the site page, and wait until the status says Tracker connected.

Keep two tabs open: this tutorial and your Privacy Analytics workspace. The examples use sample paths and names; replace them with real values from your website. Owners and administrators can create rules, sources, and dashboards; viewers can follow the analysis steps.

Tutorial 10

Track a conversion from an existing button

Turn one meaningful click into a named outcome and a two-step funnel.

◷ Self-paced
Step 1 of 6

Choose a stable action

Use a real button that represents progress, such as opening a request form. This measures the click, not a completed request.

  1. Open the page and identify one existing button.
  2. Find a stable selector such as #request-demo; replace this example with your own.
  3. Avoid a generated :nth-child() selector that may change with the layout.
  4. Keep form values and personal information out of the event.
PrerequisiteThe base tracker must already be connected. A click rule cannot prove that the form was submitted.
Step 2 of 6

Publish a click rule

Create one event with a name your team can recognize in reports.

  1. Open Tracking & events → Tracking rules.
  2. Create a draft named Request button click.
  3. Enter your selector, choose Click, and use request_demo_clicked as the event name.
  4. Set the optional page path only if this button exists on one path.
  5. Save the draft, then select Publish.
CheckVisit the page, click once, and look for the event in Engagement after processing.
Step 3 of 6

Name the conversion

Mark that same event as an outcome; the conversion definition does not create the event by itself.

  1. Open Goals & funnels for the same site.
  2. Under Conversion definitions, create Request started.
  3. Set Conversion event name to request_demo_clicked exactly.
  4. Confirm the definition is active and inspect its count for a range containing your test.
Interpret correctlyThis is a request-start conversion. Use a separate completion event if you need completed submissions.
Step 4 of 6

Verify the published rule

Do not build a conversion on an event that has never arrived.

  1. Reload the target page after publishing.
  2. Click the intended button once.
  3. Check the event name in Engagement after processing.
  4. If absent, inspect the page path and selector before creating more definitions.
Check before continuingDraft changes are not collected until published; a rule can also stop matching after a website redesign.

Step 5 of 6

Distinguish attempt from completion

A click can overstate a business outcome.

  1. Name this conversion Request started, not Request completed.
  2. If you need completion, arrange a separate event after a successful submission.
  3. Keep the two events separate when reviewing conversion rates.
Check before continuingThe browser should never send form values, email addresses, or other personal input.
✓Start event
✓Completion event
3No form data
Step 6 of 6

Compare visits with clicks

A small funnel shows how many sessions reached the pricing page before the request click.

  1. Under Funnel definitions, name a new funnel Pricing to request.
  2. Make step 1 a Pageview with path /pricing.
  3. Make step 2 an Event named request_demo_clicked.
  4. Create the funnel, then open both steps in the Goals report for a period containing test traffic.
  5. For session ordering and drop-off, continue with the full funnel walkthrough.
You are done whenThe event, conversion, and ordered funnel all show data after processing. Counts can differ because funnels count eligible sessions.

Tutorial 11

Build an ordered funnel

Define two real steps, verify ordered sessions, and read drop-off carefully.

◷ Self-paced
Step 1 of 6

Choose a completed journey

A funnel should represent one real visitor journey, not every page on your site.

  1. Write down the start action and the success action.
  2. Use two steps to begin, such as /pricing then trial_started.
  3. Confirm both actions are already tracked before creating the funnel.
Check before continuingYou can find both steps separately in reports or recent event data.
✓Start
✓Success
3Tracked
Step 2 of 6

Distinguish an attempt from success

A click is not always a completed conversion.

  1. If trial_started fires only after a successful signup, register it under Conversion definitions in Goals & funnels.
  2. Use Conversion for that funnel step and enter the exact event name.
  3. If you only track the button click, choose Event and label it as an attempt rather than a signup.
Check before continuingYour final step describes what actually happened, not what the visitor intended.
✓Click
✓Completion
3Clear label
Step 3 of 6

Enter the ordered steps

The app counts sessions reaching each step in order.

  1. Open the site’s Goals & funnels page.
  2. Find Create a funnel below Funnel definitions.
  3. Enter a Funnel name, then a Label, Type, and Path or event name for steps 1 and 2.
  4. Choose Pageview for /pricing and Conversion for trial_started in this example.
Check before continuingThe path and conversion name match the values collected by your site exactly.

✓Step 1

Step 4 of 6

Save and make a valid test

A funnel needs events from the same session in the correct order.

  1. Select Create funnel.
  2. In one browser session, visit the start page before completing the final action.
  3. Wait for processing and open the funnel report for a range that includes the test.
Check before continuingThe test session can reach step 2 only after it reached step 1.
✓Save
✓Same session
3Correct order
Step 5 of 6

Read the drop-off

The funnel reports ordered sessions, not every person who ever clicked a button.

  1. Compare the session count on each step.
  2. Read the completion rate and drop-off shown in the report.
  3. Check the date range and whether enough traffic exists before drawing a conclusion.
Check before continuingYou can explain what the denominator is and where the largest loss occurs.
✓Step counts
✓Completion

Step 6 of 6

Investigate a zero or surprising result

A missing step can be a tracking mismatch rather than user behavior.

  1. Check each step’s Type and exact Path or event name in the definition.
  2. Confirm the conversion fires on completion, not before it.
  3. Repeat the actions in order within one session and allow aggregation to finish.
  4. If the funnel is no longer relevant, use its Disable action rather than treating stale counts as current.
You are done whenA repeatable test reaches the expected steps, or you know which tracked action is missing.

Tutorial 12

Use automatic link events

Measure outbound destinations and downloads without writing a custom rule for each link.

◷ Self-paced
Step 1 of 6

Pick a useful question

Automatic events work best for broad link behavior.

  1. Choose outbound destinations, file downloads, or both.
  2. Decide what you will do with the answer, such as finding useful external resources.
  3. Keep a custom rule for a specific button or campaign action.
Check before continuingAutomatic events report categories; they do not identify people or record form values.
✓OutboundDestination host
✓DownloadFile type
3Specific CTACustom rule
Step 2 of 6

Enable only what you need

Both switches start disabled and can be changed independently.

  1. Open the site’s Tracking & events page.
  2. Find Automatic events.
  3. Select Track outbound links or Track file downloads.
  4. Select Save automatic events.
Check before continuingDo not enable tracking simply to fill a report; start from the question.

Step 3 of 6

Perform a safe test

Use a real link from the registered website.

  1. Open an external link that leaves your site, or download a recognized file type.
  2. Make sure the browser actually follows the link or starts the download.
  3. Note the UTC time and selected site.
Check before continuingAn internal link is not an outbound-link event.

Step 4 of 6

Verify the event in reports

Allow collection and processing before reading totals.

  1. Open Engagement for a range including the test.
  2. Look for outbound_link or file_download.
  3. Compare its trend or total with the specific question you wrote down.
Check before continuingRealtime may arrive before aggregate reports; an empty aggregate immediately after the click is not a failure.
✓EventCorrect name

Step 5 of 6

Understand what is excluded

The privacy boundary is part of the feature.

  1. Outbound-link events contain only destination hostnames.
  2. File-download events contain only recognized extensions.
  3. Do not expect link text, destination path, query string, or form fields.
Check before continuingIf you need item-level context, use a carefully scoped object mapping with a non-personal ID.
✓HostAllowed
✓ExtensionAllowed
3Personal dataExcluded
Step 6 of 6

Review and adjust

Keep the switches only while they answer a useful question.

  1. Check the event volume after real traffic.
  2. If a switch adds noise, turn it off and save.
  3. If no test event appears, verify the tracker, link type, date range, and worker.
You are done whenYou are done when the desired event appears with privacy-safe fields and the data informs a decision.

Tutorial 24

Find where data stopped

Separate a missing browser event from a delayed report before changing configuration.

◷ Self-paced
Step 1 of 6

Confirm the tracker sees the page

Start at the website, not at the chart.

  1. Open the affected site in Analytics and check its Tracker connected status.
  2. Visit the exact page you expect to measure.
  3. Open the site’s Realtime activity to look for a new pageview.
  4. If no visit appears, compare the site’s registered origin and installed snippet with the live page.
Interpret carefullyA connected status proves earlier traffic arrived; it does not prove this exact page still sends events.
✓Correct siteOrigin matches
2Exact pageRealtime visit
3ReportAfter processing
Step 2 of 6

Check the event itself

For a rule-based action, an empty chart may begin with a selector that no longer matches.

  1. Open Tracking & events → Tracking rules.
  2. Confirm the rule is published and the page-path condition matches.
  3. Check selector health, then perform the intended action on the real page.
  4. If it still does not arrive, inspect the browser’s collection request and errors.
Do not over-read the health label“No recent matches” may mean no qualifying visitors, not a broken selector.
Step 3 of 6

Separate delay from loss

Realtime and aggregate reports update on different schedules.

  1. Choose a date range containing the event; check the UTC date around midnight.
  2. Compare Realtime with Engagement or the relevant report.
  3. Open Data quality and review collection, volume, aggregation, and source freshness.
  4. If Realtime has data but aggregates do not update after processing, ask an administrator to check the worker and scheduler.
Next place to lookSystem administrators can check System health; site viewers may not have access.
✓RealtimeEvent arrived
2AggregateWait for processing
3WorkerCheck if delayed
Step 4 of 6

Inspect one failed collection request

The browser can tell you whether a page sent an event at all.

  1. Open developer tools on the affected page.
  2. Look for the tracker script and the batch request.
  3. Note whether the request is absent, blocked, rejected, or successful.
Check before continuingRecord the HTTP status and browser error; do not include secrets or visitor data in the report.
✓Tracker loaded
✓Batch sent
3Response checked
Step 5 of 6

Check filters before blaming the queue

Received data can be deliberately excluded from reports.

  1. Check the selected UTC period and traffic-quality classification.
  2. Consider internal-network and probable-bot exclusions.
  3. Compare the affected page with a known healthy page on the same site.
Check before continuingOnly investigate rollups after verifying the event arrived and is eligible for reporting.
✓Period correct
✓Traffic eligible
3Compare known page
Step 6 of 6

Record the first failing step

Give the person fixing the issue enough information to reproduce it.

  1. Note the site, exact path, event name, UTC time, and selected period.
  2. Record whether the pageview appeared in Realtime and whether the rule matched.
  3. Record whether the aggregate report updated later.
  4. Follow the matching section of the Troubleshooting guide.
You are done whenYou can identify whether the issue is browser collection, rule matching, or report processing.
