Managed server

Laravel Forge

On Forge, use Docker Compose for the application runtime and let Forge manage the Ubuntu server, repository checkout, Nginx, TLS, firewall, and deployment trigger.

i

The application requires PHP 8.5. Docker is the recommended Forge path because it supplies the tested PHP version together with PostgreSQL 18, Redis 8, Horizon, and the scheduler.

Deployment architecture

Internet → Forge Nginx and TLS → 127.0.0.1:8080 → app
                                                     ↳ PostgreSQL
                                                     ↳ Redis
                                                     ↳ Horizon
                                                     ↳ scheduler

Provision the server and site

  1. Create an Ubuntu 24.04 server.

    Use at least two CPU cores and 4 GB of memory as a starting point.

  2. Install Docker from its official apt repository.

    Add the forge user to the docker group and reconnect.

  3. Create the site and connect the repository.

    Keep the site's web directory set to /public.

  4. Create and edit .env.

    Use .env.example as the starting point in Forge’s Environment editor for a new installation. Preserve existing secrets. Set the public HTTPS URL, enable secure cookies, and configure mail. The deployment script runs ./bin/setup to fill missing or empty secrets while preserving the shared environment symlink.

Do not create a Forge database, regular queue worker, Horizon daemon, or scheduled job for this Docker deployment. Compose already owns those services.

Configure Forge Nginx

Replace the site's main location / block with the reverse-proxy configuration from the general installation guide. Add client_max_body_size 8m; in the server block for CSV uploads. Save the configuration, install a Let's Encrypt certificate in Forge, and enable HTTPS redirection.

Deployment script

Replace Forge’s entire native Laravel deployment script with this Docker release script. Do not run host Composer, npm, Artisan migrations, or $RESTART_QUEUES().

set -e

$CREATE_RELEASE()

cd "$FORGE_RELEASE_DIRECTORY"
export IMAGE_TAG="release-$(basename "$FORGE_RELEASE_DIRECTORY")"

./bin/setup

# All application services use this same image; build it once.
docker compose build --pull app

if ! docker compose up -d --no-build --remove-orphans --wait --wait-timeout 180; then
    docker compose ps -a
    docker compose logs --tail=100 init postgres app worker scheduler
    exit 1
fi

docker compose exec -T app php artisan optimize

$ACTIVATE_RELEASE()

All application services share one image. The Dockerfile creates storage and cache directories before Composer boots Laravel, and the build excludes Forge’s host storage symlinks. The initializer runs migrations; a failed startup prints container logs. No separate Forge database is needed.

Compose selects PostgreSQL and ignores stale DB_URL values. Before first startup, choose the database username, name and password. An existing database keeps its original credentials even after environment values change.

Release activation does not make container replacement zero-downtime. Brief interruptions are possible, and reverting Forge’s current symlink does not roll back containers or migrations. Avoid simultaneous deployments.

HTTPS and trusted proxies

Keep APP_URL on HTTPS and set SESSION_SECURE_COOKIE=true. Forge Nginx must forward proxy_set_header X-Forwarded-Proto $scheme;. After the first start creates the network, inspect its gateway:

docker network inspect privacy-analytics_default

Find IPAM.Config.Gateway and set Forge’s TRUSTED_PROXIES to that address, then redeploy. For a standard Docker bridge it may be 172.18.0.1; use the actual value. Do not trust every address. Without proxy trust, the browser may block HTTP stylesheets and scripts on the HTTPS page.

First start and verification

cd /home/forge/analytics.example.com/current
export IMAGE_TAG="release-$(basename "$(pwd -P)")"
docker compose ps
docker compose logs init
curl --fail http://127.0.0.1:8080/health

Run the deployment script first, then use these checks from the active release. To investigate a failed deployment, use its release directory and image tag instead. After Forge has issued the certificate, verify the public health URL and complete /install. Enable quick deployments only when every push to the selected branch should go directly to production.

Database authentication recovery

If startup times out, read docker logs --tail 200 privacy-analytics-init-1. A healthy database probe does not prove that application credentials work. PostgreSQL initializes roles only when the volume is empty; current container environment settings do not prove a role exists.

Find the original DB_USERNAME in your installation records. In an interactive SSH terminal, replace original_user below:

docker exec -it privacy-analytics-postgres-1 psql -U original_user -d postgres

At the PostgreSQL prompt, inspect the roles and databases. If needed, set that user’s password:

\du
\l
\password original_user
\q

Set Forge’s DB_USERNAME to the existing role, DB_DATABASE to the existing application database and DB_PASSWORD to the password entered above, then redeploy. An installation initialized with user forge may have neither an analytics nor a postgres role. Do not reset the volume to fix credentials.

Backups on Forge

Forge's database backup feature cannot see PostgreSQL inside the supplied Compose stack. Run ./bin/backup, move the completed directory to encrypted off-site storage, and regularly test a restore.

!

Never run docker compose down -v in production. The -v option deletes the PostgreSQL, Redis, and private application-storage volumes.

Native Forge alternative

If Forge offers PHP 8.5 on the selected server, you may use host PostgreSQL, host Redis, PHP-FPM, a Forge Horizon daemon, and Forge's minutely Laravel scheduler. Set database and Redis hosts to 127.0.0.1, build assets with Node 22.12 or newer, and use the native commands from the installation guide.

For production checks, backups, upgrades, and recovery after deployment, continue with Production operations and Troubleshooting.
