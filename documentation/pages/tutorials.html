Before you start

Complete these once. After that, every tutorial can be followed by a site owner without changing website code.

  1. 1
    Add your website

    Open Sites, select Add site, and enter the exact public URL including https://.

  2. 2
    Install the base tracker

    Copy the single script shown on the site page into your website. This is the only deployment required for these tutorials.

  3. 3
    Confirm the connection

    Visit your website once, return to the site page, and wait until the status says Tracker connected.

Keep two tabs open: this tutorial and your Privacy Analytics workspace. The examples use /catalog/; replace it with the real path from your website.

Tutorial 01

Track a whole URL collection

Create one mapping that discovers every object detail page automatically.

◷ 6 min
Step 1 of 4

Recognize the stable pattern

Start with two real detail pages. Compare their paths and identify the segment that changes for each item.

  1. Open two detail pages from the same collection.
  2. Copy only the path after the domain.
  3. Confirm the changing value is stable and contains no personal data.

Step 2 of 4

Turn the changing segment into a wildcard

Create the mapping and replace the changing segment with one wildcard.

  1. Open your site in Privacy Analytics.
  2. In the left navigation, click Tracking & events.
  3. Scroll to Object mappings and expand Create an object mapping.
  4. Select the Detail pages template.
  5. Enter /catalog/* in Page URL pattern.
Check before continuingID source is Current page URL and Capture group is 1.
Detail pagesTemplate
Step 3 of 4

Describe what should be recorded

Complete the remaining fields. Use a type that your team will still understand months from now.

  1. Set Mapping name to Catalog detail page views.
  2. Set Object type to a lowercase value such as catalog_item.
  3. Choose View for Record as.
  4. Choose Page opens for When it happens.
  5. Review the summary, then select Publish mapping.
ImportantThe object type is your choice. Do not copy catalog_item if another term describes your data better.
Step 4 of 4

Trigger and verify the first result

Use a real visit to confirm the whole path from browser to report.

  1. Open a matching detail page in a new tab.
  2. Reload it once after the mapping is published.
  3. Return to Privacy Analytics and open Object analytics.
  4. Filter by your object type and look for the captured key.
  5. If it is not visible yet, allow the queue and rollup to finish, then refresh.

Open the listing in Visual Designer

  4. Wait for the preview to load, then select one complete card—not only its title or image.

Choose Reusable object

Tell the designer that each matching card represents a separately reportable item.

  1. In the right settings panel, choose Reusable object.
  2. Enter a clear mapping name.
  3. Enter your own lowercase Object type.
  4. Confirm the selected-element preview still highlights every repeated card.

Step 3 of 5

Read the ID from each card link

The card selector finds the repeated container. The link pattern extracts a different key from the link inside each container.

  1. Set ID source to Link inside selected element.
  2. Enter the detail-link pattern, such as /catalog/*.
  3. Set Capture group to 1.
  4. Optionally select the title inside the card as the display name.
  5. Check that the preview shows the expected key for the selected card.

  4. Enable Send once per page to avoid repeat counts while scrolling.

Tutorial 03

Model nested objects

Connect a child object to its parent using two segments from the same URL.

◷ 7 min
Step 1 of 4

Find both keys in the URL

Use a real child page and label the two stable values before configuring anything.

  1. Open one child detail page.
  2. Copy its path without the domain or query string.
  3. Identify the parent value and the child value.
  4. Confirm both values are stable, non-personal identifiers.
Example/courses/design/lessons/contrastParent key: design · child key: contrast
/courses/design/lessons/contrast
ParentChild
Step 2 of 4

Create two capture groups

Each wildcard captures one value, numbered from left to right.

  1. Open Tracking & events.
  2. Expand Create an object mapping.
  3. Select the Nested objects template.
  4. Enter /courses/*/lessons/* as the page pattern.
  5. Read the preview: group 1 should be the parent and group 2 the child.
Do not reverse themThe first * is always group 1; the second is group 2.
/courses/*/lessons/*

Step 3 of 4

Assign child and parent types

Describe both sides of the relationship using your own product vocabulary.

  1. Set the main Object type to the child type, such as lesson.
  2. Set its capture group to 2.
  3. Enable Parent object.
  4. Set the parent type to course and its capture group to 1.
  5. Choose View on Page opens.
Expected relationshiplesson:contrast belongs to course:design.

Step 4 of 4

Publish and verify both objects

The first accepted child action can create the parent, create the child, and connect them.

  1. Publish the mapping.
  2. Open a matching child page and reload it once.
  3. Open Object analytics and locate the child.
  4. Open its detail report and find Related objects.
  5. Confirm the expected parent is shown.

Tutorial 04

Use a regular expression

Handle a URL format that a simple wildcard cannot describe precisely.

◷ 7 min
Step 1 of 4

Confirm that a wildcard is insufficient

Use regex only when you need to validate or ignore parts of a path rather than capture every changing segment.

  1. Collect two or three real example paths.
  2. Write down exactly which substring should become the object key.
  3. Try to express the structure with wildcards first.
  4. Continue with regex only when a wildcard captures unwanted values.
Example problemIn /store/en/p-sku-10042, ignore the locale and p- prefix; keep only sku-10042.
Wildcard/store/*/*Captures too much
Regular expression^/store/[a-z]{2}/p-(…)$Precise match ✓
Step 2 of 4

Create one precise capture group

The fixed parts match literally. Parentheses wrap the only value that should become the object key.

  1. Open Tracking & events and create an object mapping.
  2. Choose Custom structure.
  3. Choose Regular expression as the pattern type.
  4. Paste the expression without surrounding / delimiters.
  5. Set the capture group to 1.
Pattern^/store/[a-z]{2}/p-([A-Za-z0-9_-]+)$^ and $ require the whole path to match.
^/store/[a-z]{2}/p-([A-Za-z0-9_-]+)$capture group 1
Step 3 of 4

Test valid and invalid paths

A good expression extracts the expected key and rejects paths outside the intended collection.

  1. Test one real matching path.
  2. Confirm group 1 returns only sku-10042.
  3. Test another locale and product key.
  4. Test an unrelated URL and confirm it does not match.
  5. Make sure the extracted key contains no personal data.
Do not publish yet ifThe result includes p-, the locale, a slash, or the entire URL.
Test path/store/en/p-sku-10042
Match
Group 1sku-10042
Step 4 of 4

Publish, trigger, and leave context

Finish the mapping and give future administrators enough information to maintain it.

  1. Name it Store product pages — locale URL or another descriptive name.
  2. Choose your object type, action, and trigger.
  3. Publish the mapping.
  4. Visit a matching page and trigger the action.
  5. Verify the captured key in Object analytics.
You are done whenThe expected object appears and a nonmatching path creates no object.
