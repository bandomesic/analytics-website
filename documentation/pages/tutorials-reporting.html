Before you start

The object-data overview needs no setup. Complete these once for hands-on tracking tutorials; reporting tutorials can use a site that already has data.

  1. 1
    Add your website

    Open Sites, select Add site, and enter the exact public URL including https://.

  2. 2
    Install the base tracker

    Copy the single script shown on the site page into your website. Most tutorials need no further website deployment; use a stable existing selector for interaction rules.

  3. 3
    Confirm the connection

    Visit your website once, return to the site page, and wait until the status says Tracker connected.

Keep two tabs open: this tutorial and your Privacy Analytics workspace. The examples use sample paths and names; replace them with real values from your website. Owners and administrators can create rules, sources, and dashboards; viewers can follow the analysis steps.

Tutorial 17

Build a dashboard around one question

Create a repeatable view for a team, then check that its data and sharing settings make sense.

◷ Self-paced
Step 1 of 6

Name the decision first

For example: “Which channels bring engaged visitors?” Choose a template that gives you a starting structure.

  1. Open your site’s Custom dashboards.
  2. Enter Acquisition quality as a dashboard name.
  3. Choose the Campaign template and create the dashboard.
  4. Keep only tabs and blocks that help answer this question.
PrerequisiteUse a site with enough traffic for a meaningful source breakdown.
Step 2 of 6

Add an explanatory block

One headline number needs a breakdown or trend beside it.

  1. Open the new dashboard and enter edit mode.
  2. In the settings panel, choose a native analytics source and a traffic metric.
  3. Choose a display appropriate to the metric, then add the block.
  4. Give it a title that says what it measures, such as Visits over time.
CheckThe block should show real data for the selected dashboard date range.
Step 3 of 6

Save a focused exploration

Use Explore when the question needs a dimension that a template block does not show clearly.

  1. Open Explore for the same site.
  2. Choose a metric and a source or campaign dimension.
  3. Run the exploration and check that the rows answer the question.
  4. Under Keep this view, choose the new dashboard and select Add to dashboard.
Why save itThe dashboard block remains a live view, so the team can revisit the same question next week.

Step 4 of 6

Choose blocks that explain each other

A number alone rarely tells a team what to do.

  1. Put a traffic headline beside a source breakdown or trend.
  2. Remove a template block that does not answer the dashboard question.
  3. Use clear labels and note where a metric comes from.
Check before continuingEvery block should help explain, qualify, or track the same decision.

Step 5 of 6

Check mixed source dates

External datasets can have different time coverage from site analytics.

  1. Change the dashboard date range and watch which blocks respond.
  2. Check each external dataset’s date column.
  3. Label all-time values rather than presenting them as part of the selected period.
Check before continuingA healthy connection does not prove that two metrics share a comparable time window.
✓Date filter

Step 6 of 6

Review before sharing

Make sure someone else can read the dashboard without an explanation from you.

  1. Return to the dashboard and set a complete reporting period.
  2. Check each block’s title, data source, date coverage, and empty states.
  3. Use Presentation view to review the layout.
  4. If creating a share link under Share & report, review every tab, choose a short expiry, and add a password when needed. The shared view uses the last 30 days.
You are done whenA colleague can identify the question, period, source, and main finding from the dashboard alone.

Tutorial 18

Share a dashboard safely

Review the report, create a protected link, and see exactly what a recipient can open.

◷ Self-paced
Step 1 of 6

Choose a finished dashboard

Start with a dashboard whose audience and purpose are clear.

  1. Open Custom dashboards for the intended site.
  2. Choose a dashboard with a useful question, readable titles, and current data.
  3. Confirm you can manage the site; the share-link form is shown to site managers.
Check before continuingYou know who needs this report and why they should see every tab.
✓AudienceNamed
✓DashboardReady
3AccessCan manage
Step 2 of 6

Review the version recipients will see

The shared page is read-only and uses the last 30 days, regardless of your current editor date range.

  1. Inspect every tab and block, including tabs you rarely open.
  2. Check names, source labels, empty states, and values for the last 30 days.
  3. Remove anything that the intended audience should not receive.
Check before continuingA recipient can understand the period and source of each visible number.
✓All tabsReviewed
✓Last 30 daysChecked
3Sensitive blocksRemoved
Step 3 of 6

Choose the link protection

Under Share & report, the link can expire after 7, 30, or 90 days.

  1. Choose the shortest expiry that covers the recipient's review window.
  2. Add a password when the report leaves the signed-in workspace; it must be at least six characters.
  3. Select Create link.
Check before continuingThe confirmation contains the new link, and it appears under Protected share link with its expiry.
Step 4 of 6

Test as a recipient

Your signed-in view can hide access problems, so test the new link in a separate private browser window.

  1. Open the share URL without a workspace session.
  2. If protected, confirm the password page appears and the correct password unlocks it.
  3. Check the site, title, tabs, values, and last-30-days label.
  4. Verify there are no edit controls.
Check before continuingThe recipient sees only the intended read-only report, without signing in.
✓Fresh sessionOpened
✓PasswordTested
3Read-onlyVerified
Step 5 of 6

Send only what is needed

Anyone holding an unprotected link can open it until expiry; a password adds a separate gate.

  1. Share the URL only with the intended recipient.
  2. Send the password through a separate channel when one is set.
  3. Tell the recipient the expiry and the report's 30-day period.
Check before continuingThe recipient has the right access details and knows when the link stops working.
✓RecipientIntended
✓URLShared
3ExpiryCommunicated
Step 6 of 6

Plan for expiry

The current interface does not offer a per-link revoke control.

  1. Keep track of the expiry shown beside Open share link.
  2. If the audience or dashboard content changes, review the active link and its remaining life.
  3. For the next review, create a new short-lived link after checking the dashboard again.
You are done whenA recipient can open the intended read-only report, and you know when that access expires.

Tutorial 19

Schedule a useful email report

Send a reviewed dashboard on a weekly or monthly cadence and verify delivery.

◷ Self-paced
Step 1 of 6

Make the email worth opening

The email contains a compact, last-30-days view of the dashboard, so first check that the report stands on its own.

  1. Open the dashboard and review every tab and block.
  2. Use titles that identify the metric and source without relying on a meeting explanation.
  3. Choose a recipient who needs a recurring update, not a one-time link.
Check before continuingThe dashboard gives the recipient a clear result and a reason to act.
✓TabsReviewed
✓TitlesClear
3AudienceRecurring need
Step 2 of 6

Check the delivery path

Saving a schedule does not prove that email can reach an inbox.

  1. Ask the administrator to confirm a real mail transport; MAIL_MAILER=log does not deliver.
  2. Confirm the scheduler and background worker are running.
  3. Use your own reachable address for the first schedule, if possible.
Check before continuingYou know who can inspect mail, scheduler, and worker health if delivery fails.
✓MailConfigured
✓SchedulerRunning
3WorkerRunning
Step 3 of 6

Save one recipient and cadence

Under Share & report → Scheduled email, enter a recipient and choose weekly or monthly.

  1. Enter the address that should receive the report.
  2. Choose Weekly for operational review or Monthly for a slower decision cycle.
  3. Select Schedule report.
Check before continuingThe recipient and frequency appear below the form; the schedule is saved, not sent instantly.
Step 4 of 6

Know when it will be sent

The application checks due dashboard reports once a day; weekly and monthly are recurring intervals, not a chosen weekday or calendar date.

  1. Allow the next scheduled run for the first report.
  2. Do not treat the saved schedule as an immediate send or a delivery receipt.
  3. If you submit the same recipient again, its frequency is updated instead of adding another row.
Check before continuingYou can explain why a newly saved report has not reached the inbox yet.
✓SavedNow
✓Due checkDaily
3InboxAfter queue
Step 5 of 6

Verify the actual email

The interface's sent time records when the report was queued, so check the recipient inbox too.

  1. Confirm the email arrives after the due check.
  2. Check the subject, dashboard name, date, and last-30-days label.
  3. Compare a few values with the dashboard and confirm every intended tab is represented.
  4. If it does not arrive, ask the administrator to inspect the queue, scheduler, and mail transport.
Check before continuingA real email arrived with the expected data; a queue timestamp alone is not proof of delivery.
✓InboxReceived
✓PeriodLast 30 days
3ValuesChecked
Step 6 of 6

Keep the schedule useful

A recurring report should change when the audience or question changes.

  1. After a few sends, ask whether the recipient uses it.
  2. Update the dashboard before its next send if a block or label is stale.
  3. Use Remove beside the recipient to stop an unnecessary schedule.
You are done whenThe right recipient receives a readable report on the intended cadence, and you know how to stop it.
✓RecipientConfirmed
✓CadenceUseful
3RemoveAvailable

Tutorial 23

Set an alert you can trust

Preview an email, choose a meaningful threshold, and verify delivery settings.

◷ Self-paced
Step 1 of 6

Choose one signal with enough history

An alert is useful when it points to a change someone will act on.

  1. Open Email alerts for the site.
  2. Pick one card, such as Traffic drops or Important page changes.
  3. Read the minimum-volume note under that card before enabling it.
Check before continuingThe site has enough baseline activity for the chosen alert to be meaningful.
✓Signal
✓Baseline
3Action
Step 2 of 6

Preview what arrives

Email previews use example data and do not send mail.

  1. Select Preview every email →.
  2. Open the template for the alert you chose.
  3. Check that its subject, period, metric, and link would help the recipient investigate.
Check before continuingYou know what the notification says before subscribing.
✓Preview
✓Period
3Action link
Step 3 of 6

Set a threshold and scope

A sharp enough change should deserve attention without creating noise.

  1. Return to Email alerts.
  2. For a change alert, choose Notify when change reaches a threshold such as 30%.
  3. For an important-page alert, enter the exact Page path.
  4. For conversion alerts, first create a browser conversion in Goals & funnels and select its event.
Check before continuingThe path or conversion event matches your real setup exactly.
✓Threshold
✓Path or event
3Meaning
Step 4 of 6

Subscribe deliberately

Each teammate controls their own alert subscriptions.

  1. Turn on Email me about this for the chosen card.
  2. Select Save alert.
  3. Confirm the card now shows On and the expected threshold or event.
Check before continuingYour own subscription is on; another teammate must enable theirs separately.
✓Toggle on
✓Save
3Status on
Step 5 of 6

Check delivery conditions

A saved alert still needs background evaluation and working mail.

  1. If the page says email is in log mode, configure a real mail provider before expecting inbox delivery.
  2. Remember alerts are checked hourly and some compare complete UTC days.
  3. If the signal occurs but no email arrives, inspect worker, scheduler, and mail health.
Check before continuingYou know when evaluation runs and where to troubleshoot a missing email.
✓Mail mode
✓UTC period
3Worker health
Step 6 of 6

Review the noise after use

An alert should stay relevant as traffic changes.

  1. Revisit the alert after enough complete days.
  2. If it fires too often, raise the threshold or narrow the watched page.
  3. If it never fires, check the baseline safeguards before lowering the threshold.
  4. Turn off subscriptions that no longer lead to action.
You are done whenThe alert has a clear owner, useful threshold, and a response when it fires.
