Before you start

The object-data overview needs no setup. Complete these once for hands-on tracking tutorials; reporting tutorials can use a site that already has data.

  1. 1
    Add your website

    Open Sites, select Add site, and enter the exact public URL including https://.

  2. 2
    Install the base tracker

    Copy the single script shown on the site page into your website. Most tutorials need no further website deployment; use a stable existing selector for interaction rules.

  3. 3
    Confirm the connection

    Visit your website once, return to the site page, and wait until the status says Tracker connected.

Keep two tabs open: this tutorial and your Privacy Analytics workspace. The examples use sample paths and names; replace them with real values from your website. Owners and administrators can create rules, sources, and dashboards; viewers can follow the analysis steps.

Tutorial 06

Use a regular expression

Handle a URL format that a simple wildcard cannot describe precisely.

◷ Self-paced
Step 1 of 6

Confirm that a wildcard is insufficient

Use regex only when you need to validate or ignore parts of a path rather than capture every changing segment.

  1. Collect two or three real example paths.
  2. Write down exactly which substring should become the object key.
  3. Try to express the structure with wildcards first.
  4. Continue with regex only when a wildcard captures unwanted values.
Example problemIn /store/en/p-sku-10042, ignore the locale and p- prefix; keep only sku-10042.
Wildcard/store/*/*Captures too much
Regular expression^/store/[a-z]{2}/p-(…)$Precise match ✓
Step 2 of 6

Create one precise capture group

The fixed parts match literally. Parentheses wrap the only value that should become the object key.

  1. Open Tracking & events and create an object mapping.
  2. Choose Custom structure.
  3. Choose Regular expression as the pattern type.
  4. Paste the expression without surrounding / delimiters.
  5. Set the capture group to 1.
Pattern^/store/[a-z]{2}/p-([A-Za-z0-9_-]+)$^ and $ require the whole path to match.
^/store/[a-z]{2}/p-([A-Za-z0-9_-]+)$capture group 1
Step 3 of 6

Test valid and invalid paths

A good expression extracts the expected key and rejects paths outside the intended collection.

  1. Test one real matching path.
  2. Confirm group 1 returns only sku-10042.
  3. Test another locale and product key.
  4. Test an unrelated URL and confirm it does not match.
  5. Make sure the extracted key contains no personal data.
Do not publish yet ifThe result includes p-, the locale, a slash, or the entire URL.

The Page URL pattern decides where the mapping runs; the regex extracts the key.

  1. Keep a page pattern that includes the intended store URLs.
  2. Enter the regular expression in Link pattern or regex (when needed).
  3. Choose Advanced regular expression and capture group 1.
Check before continuingA perfect regex cannot help if the page pattern excludes the page before extraction begins.

Step 2 of 8

Read what each action means

Different mappings answer different questions.

  1. Impression means the object became meaningfully visible.
  2. View means its detail experience opened.
  3. Link click means a link owned by the object was selected.
  4. Conversion is a separately configured outcome attributed to it.
Check before continuingA pageview is not automatically an impression, and a click is not a completed purchase.

Impression, view, and click mappings only combine when they resolve to the same object type and external key.

  1. Open the mappings that record impressions, views, and link clicks for one item.
  2. Confirm each mapping uses the same type, such as product.
  3. Check that each ID source yields the same key, such as sku-10042, on both the card and detail page.
  4. If one action appears on a second object, fix the mismatched key before interpreting CTR.

  1. Confirm an impression mapping exists before interpreting CTR.
  2. Compare the click and impression counts for the same period.
  3. Expect no useful CTR if impressions are absent or the two mappings use different IDs.
