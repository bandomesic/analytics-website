Connected data

External data sources

Bring business context into the same dashboard as product analytics. Connect a read-only PostgreSQL or MySQL database, or upload a CSV snapshot, then expose only the metrics you want the application to use.

Where to connect a source

Open a site, choose Site settings, and scroll to Connected data. Only organization owners and administrators can add or change sources. Credentials are encrypted at rest.

PostgreSQL and MySQL

Create a dedicated database user with permission to SELECT only the tables or views needed for reporting. Do not reuse an application owner, migration, or administrator account.

  1. Allow network access.

    Permit connections from the analytics server through a private network, VPN, or tightly restricted firewall rule.

  2. Create a read-only credential.

    Grant access to specific reporting tables or, preferably, purpose-built views.

  3. Enter the connection details.

    Choose PostgreSQL or MySQL, then provide host, port, database, username, and password. PostgreSQL also exposes an SSL mode.

  4. Test and connect.

    The application verifies the credential before saving the source.

!

Do not expose a database to the whole internet. Restrict the source firewall to the analytics server and require encrypted transport at the database or network layer.

Inspect the schema

Open a connected source to browse readable tables and columns. Select a table to preview up to five rows before defining a dataset. This confirms names and value shapes without importing the source database into Privacy Analytics.

Create a dataset

A dataset declares one allowed table, an optional date column, and the fields available to dashboards. For PostgreSQL, schema-qualified names such as public.orders are supported. For MySQL, use the table name.

The optional date column makes dashboard date ranges filter the external metric. Without one, the metric represents all rows and remains unchanged when the dashboard range changes.

Define metrics

Each metric needs a display name, formula key, source column, and aggregation:

AggregationUse it forExample
SumAdd numeric valuesTotal revenue from amount
CountCount rows or non-null valuesNumber of orders
AverageMean numeric valueAverage order value
MinimumSmallest valueLowest response time
MaximumLargest valueHighest contract value

Formula keys must begin with a letter or underscore and may contain letters, numbers, and underscores. Use stable keys such as revenue, orders, or refunds.

Calculated fields

A calculated field combines metrics from the same dataset using field keys, numbers, parentheses, and +, -, *, or /. Choose number, percent, or currency as the display type.

revenue / orders
(revenue - refunds) / revenue * 100
orders * average_order_value

Division by zero returns no value instead of an invalid number. A formula cannot reference a key that is not defined as a metric in that dataset.

CSV files

CSV uploads are useful for monthly targets, campaign costs, offline sales, support totals, and other snapshots that do not need a live database connection.

  • Maximum file size: 5 MB.
  • Maximum rows: 100,000.
  • The first row must contain unique column headers.
  • Dates should use ISO format such as 2026-09-23.
  • Files are stored in private application storage.

CSV upload creates a dataset and a row-count metric automatically. Add numeric metrics and calculated fields afterward. Replacing a CSV preserves its dataset only when the new file still contains every column used by existing metrics.

Blend sources

Open Decision center → Data blends to combine two numeric metrics from native or connected sources. Supported operations are add, subtract, multiply, divide, and percent-of. Examples include revenue per visitor, support tickets per customer, and return on ad spend.

Preparing for future connectors

Dashboard blocks refer to a source and a metric through a shared source registry. This keeps the presentation independent from PostgreSQL, MySQL, CSV, or native analytics and provides the extension point for later connectors such as GA4, Matomo, advertising platforms, or warehouse APIs.
