Maintain

Production operations

A reliable analytics installation needs durable backups, healthy background processes, deliberate upgrades, and clear retention. Treat the database and application key as critical production state.

Health checks

The public /health endpoint is suitable for an uptime monitor. For deeper checks, sign in as a system administrator and open System health.

docker compose ps
docker compose logs --tail=200 app worker scheduler
curl --fail https://analytics.example.com/health

The worker and scheduler publish heartbeats. A healthy web container alone does not mean ingestion, aggregation, alerts, email reports, retention, or scheduled maintenance are running.

If a component is unhealthy, follow the symptom-based checks in Troubleshooting before changing data or volumes.

Backups

The supplied wrapper creates a version-matched PostgreSQL dump, private application files, environment configuration when available, and a manifest:

./bin/backup

Move the completed directory to encrypted off-site storage. Protect it as sensitive data because it can contain administrator details, analytics data, connected CSV files, and secrets.

Test restoration

Stop the application, worker, and scheduler; restore into a new empty database; restore private storage and the original .env; run migrations; rebuild caches; restart services; and verify login, sites, ingestion, and reports.

!

Preserve the original APP_KEY. Replacing it makes existing encrypted source credentials and other encrypted application values unreadable.

Upgrades

  1. Read the release notes and back up.

    Confirm the backup exists off the server before changing the running version.

  2. Fetch the selected release.

    Use a reviewed tag or production branch rather than an arbitrary working tree.

  3. Build the new image.

    Run docker compose build --pull.

  4. Restart gracefully.

    Terminate Horizon, run docker compose up -d --remove-orphans, and let the initializer apply migrations.

  5. Verify.

    Check health, logs, login, ingestion, queue processing, aggregation, and key reports.

Scheduled work

The scheduler maintains service heartbeats, Horizon snapshots, event partitions, hourly rollups, alerts, retention, dashboard reports, and GeoIP updates. Docker runs php artisan schedule:work; a native installation must run php artisan schedule:run every minute.

Retention

RAW_RETENTION_DAYS controls raw event lifetime, while AGGREGATE_RETENTION_MONTHS controls longer-lived rollups. Choose values that support real analysis and your privacy obligations. Shorter raw retention reduces storage and exposure while keeping aggregated trends available.

GeoIP

No GeoIP database is bundled. Obtain a compatible local database under the provider's terms, place it at the configured GEOIP_PATH, and use the optional update URL for scheduled refreshes. Reports continue without it, but geographic detail remains unavailable.

Security checklist

  • Use HTTPS and secure session cookies.
  • Expose only SSH, HTTP, and HTTPS; keep application, PostgreSQL, and Redis ports private.
  • Restrict SSH, use key-based access, and apply operating-system security updates.
  • Keep APP_DEBUG=false and protect .env.
  • Use read-only external database credentials with narrow table access.
  • Review organization membership and revoke old shared dashboard links.
  • Run Composer and npm security audits during maintenance.
  • Test backups and incident procedures instead of assuming they work.

Useful commands

# Service state
docker compose ps

# Recent application and worker output
docker compose logs --tail=200 app worker scheduler

# Rebuild Laravel caches
docker compose exec -T app php artisan optimize

# Gracefully restart Horizon
docker compose exec -T app php artisan horizon:terminate

# Stop containers while preserving volumes
docker compose down
!

Never add -v to docker compose down on production data. It removes the named PostgreSQL, Redis, and application-storage volumes.
