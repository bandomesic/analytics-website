Optional measurement for any reusable object

Object analytics

Object analytics is a general-purpose layer for comparing individual things your product presents. You define the types yourself, and you can ignore this feature when page, event, goal, and funnel analytics already answer your questions.

✓

Start with standard analytics. Add Object Analytics only when you need to compare individual items, preserve their history, model parent and child relationships, or give someone access to one focused report.

▶

Prefer a visual overview? Follow how object data becomes a report. Then try stable object IDs, a detail-page or repeating-card mapping, report metrics, missing objects, and scoped report access when you need it.

How objects work

An object has a display name, a type you choose, a stable external key, and an optional parent. The external key connects activity to one specific object.

i

No fixed taxonomy. Types such as product, article, course, listing, profile, or campaign are examples only. The application does not limit you to those names.

Choose a durable identity

The type and external key together identify an object within one site. Use a key that remains stable when its display name, URL title, price, category, or owner changes. Database IDs and permanent slugs work well. Avoid names, email addresses, temporary positions, or values that contain personal data.

type: product
external key: sku-10042
display name: Trail Backpack 35L

The same key can exist under different types. For example, course:foundations and article:foundations are separate objects.

Wildcard rules

  • * captures one path segment. /items/* matches /items/item-123.
  • Several wildcards create several capture groups from left to right. In /collections/*/items/*, group 1 is the collection and group 2 is the item.
  • ** captures the remaining path, including slashes. Use it only when the stable key intentionally contains nested segments.
  • Query strings and fragments do not take part in path matching.

Regular expressions

Use a JavaScript-compatible regular expression only when a wildcard cannot describe the URL or attribute. Enter it without delimiters and select the capture group containing the stable object key.

Pattern: ^/store/[a-z]{2}/p-([A-Za-z0-9_-]+)$
URL:     /store/en/p-sku-10042
Group 1: sku-10042

Prefer wildcards when possible because they are easier for another administrator to review later.

Create a mapping with the Visual Designer

  1. Open Tracking & events.

    Select Open Visual Designer. The target page must use the registered site origin.

  2. Select one representative element.

    Choose the card, row, link, button, or form that represents the object action.

  3. Choose Reusable object.

    Enter any lowercase object type that fits your product. The field is intentionally free-form.

  4. Describe the ID.

    Provide a wildcard or regular expression for the link inside the selected element.

  5. Choose the action and trigger.

    For example, record an impression when a card becomes visible or a link click when it is selected.

  6. Test and publish.

    Test activity remains inside the designer. Publishing makes the mapping available to the installed tracker immediately.

Create a mapping in the application

Open Tracking & events, scroll past general rules and automatic events, and expand Create an object mapping. The four templates describe page structure rather than business categories:

  • Detail pages extracts one object ID from each matching page URL.
  • Repeating cards extracts a different ID from the link inside every matching element.
  • Nested objects captures a child object and its parent from the same URL.
  • Custom structure starts with regular-expression extraction.

Templates leave Object type blank. Replace every example path and selector with values from your own site before publishing.

What happens after publishing

  1. The tracker downloads the configuration.

    No additional website deployment is needed after the base tracker is installed.

  2. A matching action occurs.

    The browser extracts and validates the object key before sending an object event.

  3. The server sanitizes and queues the event.

    Origin checks, bot classification, traffic classification, and privacy filtering still apply.

  4. The object is discovered.

    If the type and key do not exist yet, the rollup creates the object automatically. A configured parent is created or linked at the same time.

  5. Aggregates become reportable.

    Object Analytics, comparisons, dashboards, and scoped reports use the daily metrics.

Register an object manually

  1. Open Object analytics.

    Select a site and choose Object analytics from the Discover navigation.

  2. Choose your type.

    Use any stable lowercase name that describes the object in your product.

  3. Set an external key.

    Use an identifier that will remain stable if the display name changes, such as a database ID or slug.

  4. Add a parent when useful.

    Parent relationships make portfolios and related objects easier to understand.

Developer API

The API is useful for application state that cannot be represented by a URL, element, or attribute. Most object tracking can use no-code mappings instead.

The tracker accepts seven standard object actions: impression, view, interaction, link click, conversion, share, and save.

privacyAnalytics.trackEntity('view', {
  type: 'your_object_type',
  id: 'item-123'
}, {
  surface: 'catalog',
  placement: 'featured',
  position: 3
});

Use surface to identify the page, screen, list, or product area. Use placement for a more specific position such as featured results, related content, or the primary card.

Collect credible impressions

An impression should represent content that became visible, rather than content that merely existed in the page markup. The tracker can observe an element and send one impression after at least half of it remains visible for one second.

const card = document.querySelector('[data-item-id="item-123"]');

const stopObserving = privacyAnalytics.observeEntity(card, {
  type: 'your_object_type',
  id: 'item-123'
}, {
  surface: 'catalog'
});

Call stopObserving() if a single-page application removes the element before the page changes.

Metrics and comparisons

  • Impressions count visible presentations of the object.
  • Daily unique reach sums privacy-safe distinct visitor estimates calculated within each day.
  • Views count opens of the object's detail experience.
  • Click-through rate divides link clicks by impressions.
  • Engagement rate compares meaningful interactions with impressions.
  • Conversions count business outcomes attributed to the object.

Use previous-period, previous-year, or custom comparisons. Each object also retains daily aggregates for a five-year year-over-year view, independently of raw-event retention.

Object reports

The overview compares every registered object and can filter by your object types. Open one to see its time series, surface and placement breakdown, annual history, tracking instructions, related objects, and portal access.

Verify a mapping

  1. Confirm the base tracker.

    The site should show Tracker connected before you troubleshoot an object mapping.

  2. Visit a matching page.

    Use a real URL that matches the page pattern and perform the configured action.

  3. Check the extracted value.

    Confirm the wildcard or regular-expression capture produces the expected stable key without spaces or personal data.

  4. Allow queued processing.

    New objects appear after the event worker and daily rollup process the accepted action.

  5. Open Object Analytics.

    Filter by the configured type and confirm the object, action count, surface, and placement.

If an object does not appear

  • Confirm the mapping is active and its page pattern matches the path exactly.
  • For cards, make sure the selected element contains a link whose path matches the link pattern.
  • For visibility, confirm the element reaches the configured percentage and duration.
  • For regular expressions, test the selected capture group and use JavaScript-compatible syntax.
  • Check Data quality and System health for ingestion, worker, or scheduler problems.
  • Remember that probable bots and non-human traffic do not create object aggregates.

Customer portal access

A site manager can grant an existing user access to one object. That user receives a focused report with date comparisons and historical performance, without access to the internal site navigation, other objects, or organization analytics.

!

Access is object scoped. Grant access only to the object the customer should see. Organization owners and administrators retain access through their normal site permissions.

Privacy model

Object events use the same sanitization, bot filtering, internal-traffic classification, and pseudonymous daily aggregation as other analytics events. Object IDs should identify content or business objects. Do not place names, email addresses, account secrets, or other personal data in object properties.
