Collection guide

Tracking and events

The lightweight browser tracker records pageviews, active engagement, and the interactions you explicitly configure. This guide explains what happens in the browser, how to model useful events, and how to verify that collection works.

✓

Start small. Install pageview tracking first, then add only the events that answer an active product or business question.

How the tracker works

The generated snippet loads tracker.js from your Privacy Analytics installation and identifies the registered site with its public ID. The tracker:

  1. Validates its configuration.

    It derives collection and configuration endpoints from its own script URL and stops safely when the public site ID or URL is invalid.

  2. Records navigation.

    It sends the initial pageview and detects browser back/forward navigation plus History API changes used by single-page applications.

  3. Queues briefly in memory.

    Events flush every five seconds, when ten events are waiting, and during page lifecycle transitions. Nothing is stored in browser cookies, local storage, or session storage.

  4. Processes asynchronously.

    The server sanitizes accepted events before Redis queueing, then Horizon writes deduplicated events and updates reports.

The tracker is dependency-free and has a 10 KB compressed size budget. Collection failures are isolated so they cannot break the tracked website.

Pageviews and engagement

A pageview contains the sanitized path, controlled UTM fields, referrer origin, timestamp, and a random event UUID. URL fragments and non-campaign query parameters are removed before transmission.

Engagement measures whole seconds while the document is visible and the browser window has focus. It sends a summarized duration when navigation or a lifecycle transition occurs. Treat this as active-time estimation rather than exact attention or reading time.

Send a custom event

Use the browser API for interactions already represented in your application code, such as completing onboarding or switching a plan. Call it after the Privacy Analytics script has loaded:

window.privacyAnalytics?.track('signup_completed', {
    plan: 'starter',
    seats: 3,
    trial: true,
});

Event names may contain letters, numbers, dots, underscores, colons, and hyphens, with a maximum length of 100 characters. Properties may be strings, finite numbers, or booleans.

Good fieldAvoidReason
plan: "starter"email: "person@example.com"Email-related keys and email-shaped values are discarded.
items: 3customer: { ... }Nested objects and arrays are not accepted.
experiment: "pricing_a"form_value: "..."Do not send free-form personal or sensitive input.

Each event accepts at most 20 properties. Keys are limited to 50 characters and string values to 200 characters. The browser and server both apply filtering.

Automatic link events

Open Tracking & events → Automatic events to enable either option independently:

  • Outbound links emit outbound_link with only the destination hostname.
  • File downloads emit file_download with only a recognized file extension.

Link text, destination paths, query strings, URL fragments, and form values are never included. Automatic events are disabled until a site manager enables them.

Create interaction rules

Rules let non-developers define an event for a matching element. A rule contains a CSS selector, event name, trigger, optional exact page path, minimum duration, visibility threshold, and once-per-page behavior.

Saving creates a draft. Publishing creates an immutable version that trackers can download. Editing a published rule leaves the live version unchanged until you publish again. You can roll back to an earlier version or archive a rule.

Use the Visual Event Designer

The designer opens your registered site with a short-lived session. Point at an element, review the selector and match count, choose whether one or all matching elements should count, and test the interaction locally.

  • Prefer data-analytics-id, another stable data attribute, or a unique ID.
  • Avoid selectors based on visual position or generated class names.
  • Use the exact page path when the same selector has a different meaning elsewhere.
  • Test mode does not send analytics events, so configuration work does not pollute reports.

General event rules are saved as drafts for review. Optional object mappings can be published directly from the designer: choose Reusable object, provide any object type your product needs, enter a link pattern such as /items/*, and the wildcard value becomes the stable ID for every matching item.

For detail pages, repeating cards, nested parent and child objects, attributes, fixed IDs, and regular expressions, read the Object mapping guide.

Verify collection

  1. Check the connection state.

    Site settings should show that at least one pageview has arrived.

  2. Use a normal browser visit.

    Open the registered origin, perform the interaction once, and wait for the in-memory flush and queue processing.

  3. Review Engagement or Goals.

    Confirm the event name appears before turning it into a conversion or funnel step.

  4. Inspect selector health.

    Recent matches indicate activity; no recent matches may also mean the element had no traffic.

Collection limits

The batch endpoint accepts at most 50 events and 65,536 bytes per request. Events older than seven days, more than one day in the future, malformed events, and requests from a different browser origin are rejected. UUID deduplication makes retries safe.

For missing events, continue with Tracker does not connect.
