What the application does

The application collects events from sites you register, processes them through a queue, and presents the resulting traffic, engagement, campaign, conversion, journey, and retention reports. You can then combine those native reports with metrics from PostgreSQL, MySQL, or CSV files.

◉

Measure

Pageviews, visitors, sessions, sources, devices, geography, engagement, campaigns, events, and traffic quality.

⌁

Understand

Conversions, ordered funnels, journeys, retention cohorts, segments, investigations, and contextual annotations.

▦

Connect

Read-only PostgreSQL and MySQL datasets, private CSV snapshots, reusable metrics, and calculated fields.

↗

Communicate

Tabbed dashboards, protected share links, exports, scheduled email reports, alerts, and a decision log.

Core concepts

ConceptPurpose
OrganizationThe team boundary. An organization contains members and one or more sites.
SiteA website or product origin with its own tracker key, reports, rules, sources, and dashboards.
EventA privacy-filtered pageview or interaction accepted from the registered site origin.
ObjectAn optional, user-defined measurable item with a stable type and key. Products, content, listings, and profiles are examples rather than fixed categories.
Data sourceNative Privacy Analytics data, an external database, or an uploaded CSV file.
DatasetAn allowed table or CSV snapshot plus a date column and reusable field definitions.
DashboardA tabbed reporting canvas containing blocks from one or more available sources.

The privacy boundary

The tracker is designed to collect useful behavioral signals without building cross-site identity profiles. The server validates the registered origin, sanitizes event properties, classifies bots and internal traffic, and applies operator-controlled retention.

Self-hosting gives the operator control of the infrastructure and data lifecycle. It does not make an installation legally compliant by itself. Your collection choices, notices, consent requirements, hosting location, access controls, and retention policy still need review for your organization and jurisdiction.

Read Privacy and security for the exact collected and discarded fields, visitor and session estimation, retention controls, and operator checklist.

Where to find things

The application sidebar is grouped by purpose. Analytics contains the standard traffic and behavior reports. Discover contains investigations, journeys, retention, optional Object Analytics, decisions, and custom dashboards. Configuration contains tracking rules, external sources, alerts, data quality, and site settings. System administrators also see System health.

Your first successful setup

  • The public and private health endpoints return a successful response.
  • The installer is closed and the first administrator can sign in.
  • The registered site shows Tracker connected.
  • A real pageview and one meaningful event appear in reports.
  • The worker and scheduler show current heartbeats in System health.
  • Backups are copied off the application server and a restore procedure has been tested.
