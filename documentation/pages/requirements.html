Server requirements

The supported and simplest production setup is Docker Compose on a current Linux server. A native Laravel deployment is also possible when every runtime and background process is configured explicitly.

Recommended server

ResourceStarting pointWhy
Operating systemUbuntu 24.04 LTSLong support window and straightforward Docker installation.
CPU2 coresLeaves capacity for the web process, Horizon, scheduler, PostgreSQL, and Redis.
Memory4 GBA practical minimum for the complete six-service Compose stack.
Storage30 GB SSDIncrease this for traffic volume, raw-event retention, CSV files, and local backups.
NetworkPublic 80/443; restricted 22The application port stays bound to loopback. PostgreSQL and Redis are never public.

Capacity depends on event volume, query range, retention, connected datasets, and concurrent users. Monitor database size, queue depth, response time, disk use, and memory after launch, then scale from observed demand.

Docker deployment

The host needs only:

  • Docker Engine with the Compose v2 plugin.
  • OpenSSL for first-run secret generation.
  • Git to clone and update the repository.
  • A reverse proxy or the supplied Caddy overlay for HTTPS.

The production image includes PHP, Composer, Nginx, compiled frontend assets, and required extensions. Compose adds PostgreSQL, Redis, the migration initializer, Horizon, and the scheduler.

Native Laravel deployment

A native installation requires the following versions and services:

Cache and queueRedis 8 with persistence and a no-eviction policy
Dependency managerComposer 2
Frontend buildNode.js 22.12 or newer and npm
Web runtimeNginx or Apache serving only public/ through PHP-FPM
Background workA process supervisor for Horizon and cron for Laravel's scheduler
!

Do not use php artisan serve in production. It is a development server and does not replace a production web server and PHP-FPM.

Domain, DNS, and TLS

Create an A record, and an AAAA record when IPv6 is configured, pointing the analytics domain to the server. HTTPS is required for production so sessions remain secure and browser requests from tracked sites are transported safely.

The public URL belongs in APP_URL, and SESSION_SECURE_COOKIE must be enabled after HTTPS works. When a reverse proxy terminates TLS, configure TRUSTED_PROXIES with the actual private proxy address or subnet seen by the application.

Email delivery

SMTP or another Laravel-supported mail transport is needed for alerts, scheduled dashboard reports, and future account messages. The default log mailer is useful while evaluating the app, but it does not send to an inbox.

Persistent storage

Back up the PostgreSQL database, the application storage volume, and the operator-managed .env file. Redis supports queues and cache but is not the permanent analytics database. Keep enough free disk space to create a local backup before transferring it off the server.
